# 为什么双击 index.html 打不开，部署到服务器后却正常？

> 一篇关于浏览器「同源策略」与 `file://` vs `http://` 协议差异的技术笔记。
> 以本项目（AI 工具全景图）为例，还原一次真实踩坑与排查过程。

---

## 一、现象

把 `ai-toolkit-map` 项目拿过来，双击 `index.html` 用浏览器打开，页面顶部出现红字：

> **数据加载失败，请检查 `aihot_data.json` 文件是否存在。**

可是文件明明就在旁边。更奇怪的是，把项目部署到 ECS（`http://aihot.gouxinjie.com`）之后，一切正常，数据完美渲染。

同一个文件、同样的代码，为什么换个打开方式就不一样？

---

## 二、先看代码：数据是怎么加载的

页面并没有把数据写死在 HTML 里，而是启动时通过 `fetch` 动态拉取：

```js
async function loadData(){
  try {
    const res = await fetch('aihot_data.json');   // ← 关键：相对路径
    if (!res.ok) throw new Error('HTTP ' + res.status);
    const json = await res.json();
    ...
  } catch(err){
    // 走到这里，就显示「数据加载失败」红字
    document.body.innerHTML = '<p ...>数据加载失败，请检查 aihot_data.json ...</p>';
  }
}
loadData();
```

`fetch` 的地址是**相对路径** `'aihot_data.json'`，浏览器会把它相对于当前页面 URL 解析成完整地址。因此，**当前页面本身是用什么方式打开的**，决定了最终请求的是哪种地址、走的是哪套安全规则。双击和部署的区别，就差在「页面 URL 的开头」——也就是**协议**（URL Scheme）上。

---

## 三、根因：浏览器的「同源策略」与 `fetch`

### 1. 什么是同源策略（Same-Origin Policy）

浏览器出于安全考虑，有一条铁律：**网页里的 JS 只能向「同源」的地址发请求**。什么是同源？三个要素全部一致才算：

| 要素 | 例子 |
|------|------|
| 协议 | `http:` / `https:` / `file:` |
| 域名 | `aihot.gouxinjie.com` |
| 端口 | `80` / `443` / `8080` |

三个都对得上，才是同源，`fetch` 才被允许。

### 2. 两种打开方式的差别

| 打开方式 | 页面 URL | `fetch('aihot_data.json')` 解析为 | 同源判断 | 结果 |
|---------|---------|----------------------------------|---------|------|
| 双击打开 | `file:///d:/MyProjects/ai-toolkit-map/index.html` | `file:///d:/.../aihot_data.json` | file 协议被特殊处理，一律禁止 | ❌ 被拦截 |
| 本地服务器 | `http://localhost:8080/index.html` | `http://localhost:8080/aihot_data.json` | 同源放行 | ✅ 正常 |
| 部署到 ECS | `http://aihot.gouxinjie.com/index.html` | `http://aihot.gouxinjie.com/aihot_data.json` | 同源放行 | ✅ 正常 |

**奇怪的地方来了**：双击时，目标地址其实也是 `file:` 协议，按「协议 + 域名 + 端口」三要素看它俩是同源的，为什么还是被拦？

### 3. 为什么 `file:` 协议被特殊对待

问题就出在这里。`file:` 协议本身**没有域名、没有端口**，浏览器无法用常规标准判断两个 `file:` 资源是否真的同源。为了安全，主流浏览器（Chrome / Edge / Firefox）干脆默认：

> **从 `file:` 页面发起的 `fetch` / XHR 请求，一律禁止。**

这是把整个 `file:` 协议当作「不信任的沙箱」来处理——即使你请求的是本地文件也不行。于是 `fetch` 直接抛错（如 `Failed to fetch` 或 `URL scheme "file" is not supported`），被 `try...catch` 捕获，最终弹出「数据加载失败」。

所以**报错信息里的「请检查文件是否存在」其实有点误导**——文件一直都在，真正的问题在协议本身。

### 4. 部署后为什么就好了

部署到 ECS 后，页面通过 `http://` 协议访问，同源判断有了明确依据：页面和 `aihot_data.json` 同属 `http://aihot.gouxinjie.com`，完全同源，浏览器放行，`fetch` 成功返回数据。

## 四、验证：用本地服务器重现「部署后正常」的效果

你不需要真的部署，本地起个静态服务器就能验证同源请求是通的：

```bash
cd D:\MyProjects\ai-toolkit-map
python -m http.server 8080
# 浏览器访问 http://localhost:8080  → 数据正常加载 ✅
```

> 我在本地实测过：用这条命令起服务后，`curl` 访问 `http://localhost:8080/aihot_data.json`，返回 `HTTP 200`，数据完整可读。

这就是 README 里一直建议「用本地静态服务器访问」的原因。

### 附：`python -m http.server 8080` 这条命令到底做了什么？

这是**避开双击限制、让页面在 `http://` 下正常加载的核心工具**，拆开来看：

| 片段 | 含义 |
|------|------|
| `python` | 调用已安装的 Python 解释器（Windows 上若提示不是命令，可能是 `python3` 或需要用 `py` 命令） |
| `-m` | `module`，让 Python 以「模块」方式运行后面的工具，而不是运行某个 `.py` 文件 |
| `http.server` | Python **自带**的 HTTP 静态文件服务器模块。它会把你**当前所在目录**当作网站根目录，提供一个简易的 Web 服务 |
| `8080` | **端口号**。服务器监听的端口。默认是 `8000`，这里显式指定为 `8080`（避开常见冲突） |

#### 它做了什么
运行后，Python 会在 `8080` 端口开启一个 HTTP 服务，把**你运行命令时所在的目录**（本例为 `D:\MyProjects\ai-toolkit-map`）作为根目录对外提供。此时：

- 浏览器访问 `http://localhost:8080` → 相当于请求根目录下的 `index.html`
- 页面里的 `fetch('aihot_data.json')` → 被解析为 `http://localhost:8080/aihot_data.json`
- 因为页面与数据**同源**（协议 http + 域名 localhost + 端口 8080 完全一致），浏览器放行，数据正常加载 ✅

#### 输出含义
启动后终端会打印一行：

```
Serving HTTP on :: port 8080 (http://[::]:8080/) ...
```

这表示服务已就绪。你可以按 `Ctrl + C` 停止它。

#### 常见问题
- **端口被占用**：`[WinError 10048]` / `Address already in use` → 换一个端口，如 `8081`。
- **提示「不是内部或外部命令」**：Python 未安装或不在 PATH → 安装 Python 并勾选「Add to PATH」，或用 `py -m http.server 8080`。
- **手机想访问**：用 `python -m http.server 8080 --bind 0.0.0.0` 监听所有网卡，再用电脑的局域网 IP 访问（但注意这会把目录暴露给局域网）。

---

## 五、小结

一句话总结：

> **双击打开失败，不是文件的问题，而是浏览器禁止 `file:` 协议页面发起 `fetch` 请求（同源策略的延伸）；部署后走 `http(s):` 协议，同源请求被放行，所以正常。**

本质是**协议（URL Scheme）不同 → 同源策略规则不同**。

| 维度 | 双击 `file://` | 部署 `http://` |
|------|---------------|---------------|
| fetch 请求 | 一律被拦截 | 同源放行 |
| 数据能否加载 | ❌ 不能 | ✅ 能 |
| 是否可日常使用 | 不适合 | 正常 |

## 六、附：想让「双击也能看」该怎么办？

如果你确实希望发给别人双击 `index.html` 就能演示，有两个思路：

### 方案 A：数据内联进 HTML（彻底解决）
把 `aihot_data.json` 的内容直接写进 `index.html` 的 `<script>`，去掉 `fetch`，数据随页面一起加载。
- 优点：双击即开，无任何服务器依赖。
- 缺点：数据和页面耦合，以后改数据要编辑 HTML；文件变大。

### 方案 B：保持数据独立 + 本地服务器（推荐日常开发）
维持现有「数据独立成文件」的架构，用 `python -m http.server` 或 `npx serve` 访问。
- 优点：数据可独立维护，架构清晰。
- 缺点：需要一个静态服务器，不能纯双击。

> 本项目当前采用方案 B。若需要改造成方案 A，只需在 `loadData()` 里改为从内联变量读取，改动量很小。
